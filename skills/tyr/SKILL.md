## Activation Contract

Use when the human invokes `/tyr <url PR>` or asks to review a GitHub or Bitbucket pull request with inline comments. Runs locally in the main thread: it asks the human before publishing.

Do not use for: reviewing the local working tree without a PR (`/code-review`), fixing code (Brokkr), validating against an OpenSpec spec (Heimdall), merging or opening PRs (Forseti).

## Hard Rules

- Follow `../_shared/communication.md` (language, tone, banned tropes, questions with their why). The banned-tropes rule also applies to every published comment and summary.
- Review **only added or modified lines** of the PR diff. Every inline comment anchors to a line on the new side of the diff; drop findings that cannot.
- Every comment uses `assets/comment.md` exactly, with the severity table there and the final line `🤖 Generated by Tyr-skill`. One finding per comment.
- The three lenses (logic, security, quality) run as **parallel subagents in one message**, briefed from `references/reviewers.md`.
- Publish nothing, approve nothing and request changes on nothing until the human says yes to the preview.
- Never edit code, push, merge, decline or close the PR. Never put secrets in a comment: mask them (`sk_live_****`).
- Never claim something was published without the ids returned by the platform.
- Repo rules (`CLAUDE.md`, `AGENTS.md`, `.editorconfig`, `phpcs.xml*`, `.eslintrc*`/`eslint.config.*`, `.stylelintrc*`, `.prettierrc*`) override `references/conventions/*`.

## Decision Gates

| Situation | Action |
| --- | --- |
| `github.com` URL | `gh` CLI (see `references/platforms.md`) |
| `bitbucket.org` URL | Atlassian MCP `discover` → `executeRead`/`executeWrite` (see `references/platforms.md`) |
| No URL | Ask for it with `AskUserQuestion`, following `../_shared/communication.md`; stop |
| Previous comments signed `Generated by Tyr-skill` | Re-review: classify each as fixed / pending / outdated (see `references/rereview.md`) |
| Jira key (`[A-Z]+-\d+`) in branch or title | `getJiraIssue`; pass acceptance criteria to the logic lens |
| Any new or pending ALTA or MEDIA | Verdict: request changes |
| Only BAJA or nothing | Verdict: approve |
| `--dry-run` | Stop after the preview |

## Execution Steps

1. Parse the URL; get PR metadata, head SHA, diff and every existing comment (`references/platforms.md`).
2. Build the changed-lines map: `file → new-side lines added/modified`. Skip lockfiles, `vendor/`, `node_modules/`, `dist/`, `build/`, `*.min.*`, generated and binary files.
3. Detect languages in the diff and load only their `references/conventions/<lang>.md`. Read repo rules from the head SHA.
4. If there are previous Tyr comments, classify them (`references/rereview.md`).
5. Launch the three lenses in parallel (`Agent`, `general-purpose`) with the brief from `references/reviewers.md`. Each returns JSON matching `assets/finding.schema.json`.
6. Merge: drop findings outside the changed-lines map, dedupe by file+line+cause (keep highest severity), turn repeats of pending Tyr comments into thread replies.
7. Compute the verdict (Decision Gates).
8. Preview to the human: findings table (severity, file:line, title), re-review status, verdict. Ask with `AskUserQuestion`, following `../_shared/communication.md`: publish all / publish without some / do not publish. Wait.
9. Publish in this order: inline comments, replies and resolutions, summary (`assets/summary.md`), then approve or request changes.

## Output Contract

- PR URL, platform and head SHA reviewed.
- Counts by severity, re-review counts (fixed / pending / outdated).
- Verdict applied, or "no publicado" with the reason.
- Ids of published comments; any publish error verbatim.
