# Formato de comentario de Tyr

## Tabla de gravedad

| Círculo | Gravedad | Cuándo |
| --- | --- | --- |
| 🔴 | ALTA | Rompe funcionalidad, pierde o corrompe datos, vulnerabilidad explotable, incumple un criterio de aceptación del ticket |
| 🟡 | MEDIA | Bug probable en casos límite, lógica nueva de riesgo sin tests, problema de rendimiento real, violación de convención con impacto (mantenibilidad, accesibilidad) |
| 🔵 | BAJA | Estilo, nombres, legibilidad, mejora opcional |

## Hallazgo nuevo (inline)

```
{círculo} [{GRAVEDAD}]: {Título corto, imperativo o descriptivo, ≤ 80 caracteres}
{Descripción detallada: qué pasa, en qué caso falla o por qué es un problema, y el impacto. Cita la regla si viene de una convención o del ticket (p. ej. "AC2 de ABC-123").}

{Fix sugerido}

🤖 Generated by Tyr-skill
```

Bloque `{Fix sugerido}`:

- GitHub, cuando el fix sustituye exactamente las líneas comentadas: bloque ` ```suggestion ` con el código final de esas líneas.
- En el resto de casos (Bitbucket, o un fix que toca otras líneas): `**Fix sugerido:**` y un bloque de código con el lenguaje (` ```php `, ` ```js `, ` ```tsx `, ` ```html `, ` ```css `).
- Si no hay un fix concreto, omite el bloque; no inventes uno.

Ejemplo:

~~~
🔴 [ALTA]: Consulta SQL construida con entrada del usuario
`$id` llega de `$_GET['id']` y se concatena en la consulta. Un valor como `1 OR 1=1` devuelve todas las filas y permite inyección SQL.

**Fix sugerido:**
```php
$stmt = $pdo->prepare('SELECT * FROM orders WHERE id = :id');
$stmt->execute(['id' => (int) $id]);
```

🤖 Generated by Tyr-skill
~~~

## Respuestas en re-revisión (en el hilo del comentario original)

Resuelto:

```
✅ Resuelto en {sha corto}: {una línea sobre cómo se ha solucionado}

🤖 Generated by Tyr-skill
```

Pendiente:

```
⏳ Sigue pendiente en {sha corto}: {qué falta}

🤖 Generated by Tyr-skill
```

Un problema nuevo introducido por el fix es un **hallazgo nuevo inline**, no una respuesta.
